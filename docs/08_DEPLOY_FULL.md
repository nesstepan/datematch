# Полная инструкция: выкладка DateMatch на бесплатный хостинг

Это этап 5 из задания («Деплой на бесплатный хостинг Vercel/Render/Netlify»). Схема: **код на GitHub → бэкенд и фронтенд на Render → база данных в Firebase Firestore**.

Почему всё на Render, а не Vercel/Netlify. Фронтенд в проекте отдаёт сам Django (шаблоны и статика), поэтому отдельный хостинг для фронтенда не нужен. Плюсы: одна ссылка, нет CORS, куки и CSRF работают без настройки. Vercel и Netlify рассчитаны на статические сайты и функции без состояния, Django с сессиями и загрузкой файлов на них поднимать неудобно. Если преподаватель требует раздельный деплой, скажите ему об этом заранее.

Время: около 30-40 минут. Нужны аккаунты: GitHub, Google (для Firebase), Render (можно войти через GitHub). Платёжная карта не нужна.

---

## Шаг 0. Проверьте проект на своём компьютере
```bash
cd datematch
python -m venv .venv
.venv\Scripts\activate            # Windows. На macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# Windows PowerShell:
$env:DJANGO_DEBUG="1"; $env:USE_MEMORY_DB="1"; $env:ADMIN_EMAILS="you@example.com"
python manage.py test             # все тесты должны пройти
python manage.py runserver        # откройте http://127.0.0.1:8000
```
Если стили на странице не появились, нажмите Ctrl+F5. Если всё работает локально, можно выкладывать.

## Шаг 1. Выложите код на GitHub
1. На https://github.com нажмите **New repository**, имя `datematch`, видимость любая (Public проще), без README и .gitignore (они уже есть в проекте).
2. В папке проекта:
```bash
git init
git add .
git commit -m "DateMatch"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/datematch.git
git push -u origin main
```
3. **Проверьте, что в репозитории нет ключей**: файла `.env` и JSON с названием `...firebase-adminsdk...json`. Они перечислены в `.gitignore`, но убедитесь на странице репозитория. Если ключ случайно попал на GitHub, считайте его скомпрометированным: в Firebase удалите этот ключ и создайте новый.

## Шаг 2. Создайте базу данных в Firebase
1. Откройте https://console.firebase.google.com → **Create a project** (Add project). Имя любое, Google Analytics отключите.
2. Слева **Build → Firestore Database → Create database**.
   * Edition: Standard (обычный режим Native).
   * Регион: ближайший к вам, например `eur3 (europe-west)`. **Регион потом не изменить.**
   * Режим правил: **Production mode**.
3. Вкладка **Rules**: удалите всё, вставьте содержимое файла `firestore.rules` из проекта, нажмите **Publish**. Эти правила запрещают любой доступ из браузера. Сервер ходит в базу через ключ администратора, ему правила не мешают.
4. Ключ для сервера: шестерёнка рядом с **Project Overview** → **Project settings** → вкладка **Service accounts** → **Generate new private key** → **Generate key**. Скачается JSON-файл. Это секрет: не отправляйте его никому и не загружайте на GitHub.
5. Индексы создавать **не нужно**: все запросы в проекте используют только равенство и сортировку по одному полю.
6. Тариф Spark (бесплатный) подходит. У него есть суточные лимиты на чтения, записи и объём хранилища (на момент написания порядка 50 тысяч чтений и 20 тысяч записей в сутки, актуальные цифры смотрите в консоли: **Usage**). Для демонстрации и защиты хватает с запасом.

## Шаг 3. Создайте сервис на Render
Способ А (проще всего, через `render.yaml`):
1. https://render.com → войдите через GitHub.
2. **New → Blueprint** → выберите репозиторий `datematch` → **Apply**. Render прочитает `render.yaml`: команды сборки и запуска, проверку `/healthz` и список переменных.
3. Render попросит значения переменных, помеченных `sync: false` (см. таблицу ниже).

Способ Б (вручную): **New → Web Service** → репозиторий, затем:

| Поле | Значение |
|---|---|
| Language / Runtime | Python 3 |
| Branch | main |
| Build Command | `pip install -r requirements.txt && python manage.py collectstatic --no-input` |
| Start Command | `gunicorn config.wsgi:application --workers 2 --threads 4 --worker-class gthread --timeout 120 --bind 0.0.0.0:$PORT` |
| Instance Type | Free |
| Health Check Path | `/healthz` |

### Переменные окружения (раздел Environment)
| Ключ | Значение | Обязательно |
|---|---|---|
| `PYTHON_VERSION` | `3.12.3` | да |
| `DJANGO_SECRET_KEY` | длинная случайная строка (в Blueprint создаётся сама; вручную: кнопка Generate) | да |
| `DJANGO_SSL_REDIRECT` | `1` | да |
| `ADMIN_EMAILS` | ваш email: пользователь с таким адресом получает админ-панель | да |
| `FIREBASE_CREDENTIALS_JSON` | **весь текст** скачанного JSON-файла: откройте его в блокноте, выделите всё (Ctrl+A), скопируйте, вставьте в значение | да |
| `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL` | данные TURN-сервера, нужны только чтобы звонки работали между разными сетями | нет |

Не задавайте `USE_MEMORY_DB`: на хостинге данные должны храниться в Firestore, а не в памяти процесса.

4. Нажмите **Create Web Service** / **Deploy**. Первая сборка занимает 3-5 минут. Ход виден во вкладке **Logs**. В конце должно появиться `Your service is live`.
5. Ссылка на сайт вида `https://datematch-xxxx.onrender.com` показана вверху страницы сервиса. Это и есть «работающий проект в интернете».

## Шаг 4. Проверка на хостинге
1. Откройте `https://ВАШ-САЙТ.onrender.com/healthz`: должно показать `ok`.
2. Откройте главную. Если первый запрос идёт около минуты, это нормально для бесплатного тарифа (см. ниже).
3. Зарегистрируйтесь с email из `ADMIN_EMAILS`: в меню появится пункт «Админ».
4. В **другом браузере или в режиме инкогнито** зарегистрируйте второй аккаунт (с другим полом/предпочтениями, чтобы вы попадали в ленту друг друга).
5. Пройдите сценарий: лайк с обеих сторон → экран «Это пара!» → чат → фото, голосовое, подарок → удаление сообщения → профиль (видео, цвет, музыка) → тёмная тема → фильтры.
6. Откройте Firebase Console → Firestore → **Data**: должны появиться коллекции `users`, `photos`, `swipes`, `matches`, `media`, `interests` и другие.
7. Звонки и голосовые сообщения работают только по HTTPS. На Render он включён автоматически. Браузер спросит разрешение на камеру и микрофон.

## Особенности бесплатного тарифа (расскажите на защите)
* **Сервис «засыпает»** через 15 минут без входящих запросов. Первый запрос после сна занимает около минуты. Откройте сайт за 2-3 минуты до начала защиты.
* **Не засыпать совсем** можно, настроив бесплатный сервис опроса (например, UptimeRobot или cron-job.org) на запрос `https://ВАШ-САЙТ.onrender.com/healthz` каждые 10 минут. Бесплатных часов на месяц 750, а в месяце около 744 часов, так что для одного сервиса их хватает.
* **Квоты Firestore.** Чат опрашивается раз в 3 секунды, уведомления раз в 8 секунд, только пока вкладка открыта. Видео и файлы хранятся в Firestore кусками, поэтому большие файлы расходуют записи и чтения. При превышении дневной квоты запросы к базе будут возвращать ошибку, и сайт покажет «База данных временно недоступна». Квоты обновляются раз в сутки.
* **Файлы.** Для настоящей нагрузки перенесите их в Cloudinary, Cloudflare R2 или Firebase Storage (платный Blaze). Нужно заменить функции `save`, `load`, `delete` в `core/media.py`.
* **Звонки** в этой версии отключены: без TURN-сервера они не соединяют людей из разных сетей. Включаются переменной `CALLS_ENABLED=1` вместе с `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL`.
* **Шрифты** Playfair Display, Manrope и Marck Script подгружаются с Google Fonts. Без доступа к ним сайт показывается системным шрифтом, ничего не ломается.

## Если что-то не работает
| Симптом | Причина и решение |
|---|---|
| Сборка упала на `pip install` | Проверьте `PYTHON_VERSION=3.12.3` и что `requirements.txt` в корне репозитория |
| Страница `Application error` / 500 | Вкладка **Logs**. Чаще всего не задан `DJANGO_SECRET_KEY` или `FIREBASE_CREDENTIALS_JSON` |
| `Firebase не настроен` | Переменная `FIREBASE_CREDENTIALS_JSON` пуста или вставлена не вся (нужен весь JSON, от `{` до `}`) |
| `Invalid JWT` / `Could not deserialize key` | В JSON повреждены переносы строк в `private_key`: вставьте содержимое файла заново, не редактируя |
| `PermissionDenied` / `Cloud Firestore API has not been used` | В Firebase не создана база (шаг 2.2) или ключ скачан от другого проекта |
| `DisallowedHost` | Задайте `DJANGO_ALLOWED_HOSTS` значением вашего домена (обычно хватает автоматического `RENDER_EXTERNAL_HOSTNAME`) |
| `CSRF` 403 при входе | Обновите страницу (Ctrl+F5); проверьте, что открываете сайт по `https://` |
| Сайт без стилей | Проверьте, что `collectstatic` есть в Build Command; нажмите Ctrl+F5 |
| Нет кнопки «Админ» | Email при регистрации должен совпадать с `ADMIN_EMAILS`; изменение переменной требует перезапуска сервиса |
| Не записывается голосовое / не работает камера | Нужен HTTPS и разрешение в браузере (значок замка в адресной строке) |
| «База данных временно недоступна» | Исчерпана дневная квота Firestore или сбой сети; подождите сутки или проверьте **Usage** в Firebase |
