# Новые функции (этап 6)

Все функции работают на том же стеке: Django + Firestore, без новых сервисов и платных тарифов.

## Что добавлено

| Функция | Где в интерфейсе | Как устроено |
|---|---|---|
| Фильтры анкет | Лента → «Фильтры» | возраст от/до, интересы (подходит любой), только с видео, только с музыкой; настройки помнятся в браузере; `GET /api/feed/?age_min=&age_max=&interests=&with_video=1&with_music=1` |
| Тёмная тема | кнопка с луной/солнцем в шапке | CSS-переменные + `data-theme`; по умолчанию берётся тема системы; выбор в `localStorage` |
| Видео в анкете | Профиль → «Видео в анкете» | MP4/WEBM/MOV до 6 МБ; в ленте у карточки кнопка «Видео»; `POST/DELETE /api/me/video/` |
| Фото, GIF, видео, голосовые в чате | скрепка и микрофон в поле ввода | тип определяется по содержимому файла, фото пережимаются (до 1280 px), лимиты: фото 5 МБ, GIF 3 МБ, видео 6 МБ, голосовое 2 МБ (до 2 минут) |
| Уведомления | колокольчик в шапке | лайки (без имени), новые пары, сообщения, звонки, достижения; опрос раз в 8 с; по желанию — системные уведомления браузера, когда вкладка в фоне |
| Скрыть себя из поиска | Профиль → «Приватность» | поле `hidden`; вас не видно в чужой ленте, пары и чаты остаются |
| Звонки (аудио и видео) | трубка и камера в шапке чата | WebRTC, сигналы идут через API (`/api/matches/<id>/signals/`) |
| Виртуальные подарки | значок подарка в поле ввода | 8 бесплатных подарков, отправляются как сообщение; оплаты нет |
| Достижения | Профиль → «Достижения», значки в ленте и чате | 13 достижений, счётчики хранятся в `users.stats` |
| Оформление профиля | Профиль → «Оформление и музыка» | цвет рамки карточки и статус (до 60 символов) |
| Любимая музыка | там же | название и необязательная ссылка (только http/https) |
| Удаление сообщений | «удалить» под своим сообщением | у собеседника появляется «Сообщение удалено», файл стирается |

## Новые API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/feed/` | + параметры фильтров, 422 если min > max |
| POST | `/api/me/settings/` | JSON: `hidden`, `accent`, `status`, `music_title`, `music_url` (любые из них) |
| POST / DELETE | `/api/me/video/` | multipart `video` / удалить |
| GET | `/media/<id>/` | файл (поддерживает `Range`, чтобы видео перематывалось); доступ только участникам пары, видео анкеты — любому вошедшему |
| POST | `/api/matches/<id>/messages/` | JSON `{text}`, JSON `{gift}` или multipart `file` (+ `kind=voice`, `duration`, `text`) |
| DELETE | `/api/matches/<id>/messages/<msg>/` | удалить своё сообщение |
| GET | `/api/matches/<id>/messages/` | теперь возвращает ещё `deleted` — id удалённых сообщений |
| GET / POST | `/api/matches/<id>/signals/` | сигналы звонка: `offer`, `answer`, `candidate`, `hangup`, `decline` |
| GET | `/api/notifications/` | список и счётчик |
| POST | `/api/notifications/read/` | JSON `{ids}`, `{match_id, types}` или `{all: true}` |
| GET | `/api/gifts/`, `/api/achievements/`, `/api/ice/` | каталоги и настройки ICE |

## Новые коллекции Firestore

* `media/<id>` и `media/<id>/chunks/<0000>` — файлы. Документ Firestore ограничен примерно 1 МиБ, поэтому файл режется на куски по 700 КБ.
* `notifications/<тип>__<кому>__<ключ>` — прочитанное уведомление удаляется.
* `matches/<id>/signals` — сигналы звонка (очищаются при новом звонке и при разрыве пары).
* В `users` появились поля: `hidden`, `video_id`, `accent`, `status`, `music_title`, `music_url`, `stats`, `achievements`.

Новые запросы по-прежнему используют только равенство и сортировку по одному полю, поэтому **индексы Firestore создавать не нужно**, правила (`firestore.rules`) не меняются.

## Что важно знать перед сдачей и деплоем

1. **Файлы лежат в Firestore.** Это работает без платных тарифов, но каждое видео 6 МБ — это примерно 9 записей, а при просмотре — столько же чтений (сервер кэширует до ~24 МБ последних файлов, браузер — сутки). Для демонстрации этого хватает. Для реальной нагрузки вынесите файлы в Cloudinary, Cloudflare R2 или Firebase Storage (нужен тариф Blaze): достаточно заменить функции `save`, `load`, `delete` в `core/media.py`.
2. **Квоты Firestore.** Чат опрашивается раз в 3 с, уведомления — раз в 8 с, звонок — раз в 1,5 с. Опрос идёт только пока вкладка открыта. На бесплатном тарифе Firebase (Spark) есть суточные лимиты на чтение и запись, они меняются — проверьте актуальные цифры в консоли Firebase перед защитой.
3. **Звонки.** Используется STUN-сервер Google. Если собеседники сидят за строгими NAT или в мобильных сетях, соединение может не установиться — тогда нужен TURN-сервер. Укажите на Render переменные `TURN_URLS` (через запятую, например `turn:turn.example.com:3478`), `TURN_USERNAME`, `TURN_CREDENTIAL`; приложение само отдаст их браузеру. Камера, микрофон и голосовые работают только по HTTPS (на Render он есть) или на `localhost`.
4. **Входящий звонок** появляется у собеседника с задержкой до 8 секунд (интервал опроса уведомлений), звонок без ответа сбрасывается через 45 секунд.
5. **Бесплатный Render засыпает** через ~15 минут простоя, а несколько процессов gunicorn не делят кэш файлов в памяти — это нормально, кэш лишь ускоряет работу.
6. Лайки приходят **анонимно**: уведомление не называет имя. Имя видно, когда лайк становится парой.
7. Ограничения, которые стоит озвучить: видео не пережимается сервером (проверяется только формат и размер); у GIF и видео нет превью-кадров; «удалено» у собеседника, который сидит на странице, появляется при следующем опросе (до 3 секунд).

## Как проверить руками (после деплоя)

1. Два аккаунта в разных браузерах. Лайк от первого → у второго в колокольчике появится «Кто-то поставил вам лайк».
2. Взаимный лайк → «Новая пара», достижение «Первая пара».
3. В чате: текст, фото, GIF и видео (скрепка), голосовое (микрофон), подарок; удалить своё сообщение и проверить, что у второго оно стало «Сообщение удалено».
4. Звонок (значок трубки) из чата → у второго всплывёт карточка «Принять».
5. Профиль: загрузить видео, выбрать цвет, ввести музыку и статус → всё видно на карточке в ленте у второго аккаунта.
6. «Скрыть мою анкету из поиска» → второй аккаунт больше не видит первого в ленте.
7. Тёмная тема (луна/солнце) и фильтры в ленте.

# Версия 3: новый дизайн и социальные функции

* **Дизайн «Таро и Амур»:** бумага с зерном, рваные края, карты Таро (римская цифра возраста сверху, имя в подписи снизу), коллаж с Амуром, облаками и розами. Иллюстрации нарисованы специально для проекта (векторные, `core/templates/art.html`).
* **Кто меня лайкнул** (`/likes/`): люди, которые поставили вам лайк. Можно ответить лайком (сразу пара) или пропустить. Счётчик в меню.
* **Страница пользователя** (`/u/<id>/`): анкета, статус, «в сети», посты. На своей странице можно публиковать посты с текстом и фото/GIF и удалять их.
* **Поиск** (`/search/`): по имени или интересу, фильтры по возрасту и цели знакомства. Скрытые анкеты и люди из чёрного списка не показываются.
* **Жалобы:** кнопка на странице пользователя и в меню чата (причина, пояснение, можно сразу добавить в чёрный список). Администратор видит жалобы в панели и блокирует пользователя либо отклоняет жалобу.
* **Чёрный список:** заблокированный человек исчезает из ленты и поиска у вас и у него, пара и переписка удаляются, написать он не сможет. Управление в личном кабинете, раздел «Чёрный список».
* **Статусы сообщений:** одна галочка (отправлено), две (доставлено), две цветные (прочитано).
* **«Печатает…»** в чате и **«в сети» / «был(а) N мин назад»** в чате, на карточках и в анкете. Статус можно скрыть в кабинете.
* **Что вы ищете:** серьёзные отношения, свидания, дружба, общение, пока не знаю. Поле в анкете, на карточке, фильтр в ленте и поиске.
* **Звонки отключены** (переменная `CALLS_ENABLED`, по умолчанию выключено): без TURN-сервера они не соединяли людей из разных сетей.

Новые API: `GET /api/likes/`, `GET /api/search/`, `GET /api/users/<id>/`, `POST /api/me/posts/`, `DELETE /api/me/posts/<id>/`, `GET/POST /api/blocks/`, `DELETE /api/blocks/<id>/`, `POST /api/reports/`, `GET /api/admin/reports/`, `PATCH /api/admin/reports/<id>/`, `POST /api/matches/<id>/typing/`. Ответ `GET /api/matches/<id>/messages/` теперь содержит `receipts`, `typing` и `other` (в сети).

Новые коллекции Firestore: `reports`, подколлекция `users/<id>/posts`. В документах пользователей появились поля `goal`, `last_seen`, `hide_online`, `blocked_uids`; в документах пар: `last_sender`, `read_at_<id>`, `delivered_at_<id>`, `typing_<id>`.

# Версия 4: удобство, плеер, посты пар

* **Карточка в ленте** переделана: фото целиком, под ним подпись с именем, ниже отдельный прямоугольник с описанием, тегами и кнопками. Длинное описание сворачивается, кнопка «Читать полностью» раскрывает его (фото при этом уменьшается).
* **Адаптив:** все размеры на телефоне уменьшены, меню и шапка компактнее, поля ввода не приближаются на iPhone. Исправлена ошибка, из-за которой длинное слово без пробелов растягивало страницу.
* **Главная страница доступна всем** (гостям и вошедшим). Для вошедших кнопки ведут в ленту.
* **Отдельные страницы:** «Профиль» (`/u/<id>/`, ваша страница с постами и достижениями), «Редактирование профиля» (`/profile/`), «Личный кабинет» (`/settings/`: приватность, чёрный список, удаление аккаунта).
* **16 цветов карточек** (плюс свой цвет): цвет влияет на рамку, подпись и фон описания.
* **Встроенный плеер песни:** по ссылке на трек из Яндекс Музыки, YouTube, Spotify, SoundCloud или на файл mp3 открывается плеер прямо на сайте. Адрес плеера строится программой из разобранной ссылки, чужой адрес во встроенный кадр не попадает. Яндекс Музыка и Spotify могут проигрывать только отрывок, если человек не вошёл у них в аккаунт.
* **Лента постов пар** (`/posts/`): свежие посты людей, с которыми у вас есть пара, и ваши. Тут же можно написать пост. API: `GET /api/posts/`.
* **Дизайн:** более зернистая бумага (шум, волокна, плёночный оттенок фото), новый чёткий логотип (сердце со стрелой, он же значок вкладки браузера).
