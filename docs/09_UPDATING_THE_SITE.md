# Как обновлять сайт, который уже работает на хостинге

Схема у вас такая: **файлы на GitHub → Render сам пересобирает сайт → данные лежат в Firebase**. Поэтому обновление сводится к одному: положить новые файлы в репозиторий GitHub. Всё остальное Render делает сам.

Ваши данные (пользователи, пары, сообщения, фото) хранятся в Firebase и **не пропадают** при обновлении кода. Ключ Firebase и переменные окружения в Render тоже остаются на месте.

---

## Способ 1. Через сайт GitHub (подходит, если `git push` не работает)

### Если файлов изменилось много (как в этой версии)
1. Распакуйте на компьютере архив `datematch_update.zip`. В нём лежат **только изменённые и новые файлы** сразу в нужных папках (`core/…`, `config/…`, `docs/…`). Полный список в файле `UPDATE_FILES.txt`.
2. Откройте https://github.com/nesstepan/datematch (вы должны быть залогинены).
3. Нажмите **Add file → Upload files**.
4. Перетащите в окно **содержимое** распакованной папки: папки `core`, `config`, `docs` и файлы рядом с ними (если есть). GitHub сохранит структуру папок и **заменит файлы с одинаковыми путями**.
5. Внизу в поле «Commit changes» напишите, что изменили (например, «Новый дизайн, поиск, жалобы»), и нажмите **Commit changes**.
6. Готово. Render заметит новый коммит и начнёт сборку сам.

Если GitHub пишет, что файлов слишком много, загрузите по частям: сначала папку `core`, потом `config` и `docs`.

### Если нужно поправить один файл
1. В репозитории откройте файл, нажмите значок карандаша (**Edit this file**).
2. Внесите правку и нажмите **Commit changes**.

### Если нужно удалить файл
Загрузка файлов **не удаляет** старые. Откройте файл на GitHub → три точки справа вверху → **Delete file** → **Commit changes**. В этой версии удалять ничего не нужно.

## Способ 2. Через git (если у вас заработает соединение с GitHub)
```bash
cd datematch
git add .
git commit -m "Что изменили"
git push
```
Если `git push` обрывает соединение, см. подсказки: смена сети (например, раздача с телефона) или SSH через порт 443.

## Что происходит после загрузки
1. Откройте https://dashboard.render.com → ваш сервис **datematch**.
2. Во вкладке **Events** появится новое развёртывание (Deploy), во вкладке **Logs** виден ход сборки. Обычно 3-5 минут.
3. Когда статус **Live**, откройте сайт и обновите страницу через **Ctrl+F5** (иначе браузер может показать старые стили).
4. Если развёртывание не началось само: на странице сервиса нажмите **Manual Deploy → Deploy latest commit**.

## Если после обновления что-то сломалось
* Откройте **Logs** на Render: последняя ошибка показана в конце. Пришлите её текст, и по нему можно понять причину.
* **Откат на прошлую версию:** вкладка **Events** → у прежнего успешного развёртывания нажмите **Rollback**. Данные в Firebase при этом не меняются.
* В GitHub можно вернуть файл: открыть его → **History** → выбрать прошлую версию → **Revert**.

## Новые переменные окружения
Иногда в новой версии появляется настройка (например, `CALLS_ENABLED`). Добавляется так: Render → ваш сервис → **Environment** → **Add Environment Variable** → ключ и значение → **Save Changes**. Сервис перезапустится сам.

## Что учесть в версии 4
* **Главная страница открыта всем**, в том числе вошедшим пользователям. В меню появились «Посты» (лента постов ваших пар) и «Профиль» теперь открывает вашу страницу. Редактирование профиля (`/profile/`) и личный кабинет с приватностью и чёрным списком (`/settings/`) стали отдельными страницами. Значок админ-панели переехал в шапку.
* **Звонки по-прежнему отключены** (`CALLS_ENABLED`).
* **Старые анкеты** работают без изменений. Цвета карточек, ссылки на песни и посты пользователей сохраняются.
* **Хостинг.** Если вы переезжаете с Render на Railway, смотрите `docs/10_DEPLOY_RAILWAY.md`. На Railway автообновление работает так же: загрузили файлы на GitHub, и сайт пересобрался.

## Правила, чтобы не терять данные
* Не загружайте в репозиторий файл `.env` и JSON-ключ Firebase.
* Не удаляйте базу Firestore в консоли Firebase: вместе с ней пропадут все пользователи.
* Перед большим обновлением откройте сайт и убедитесь, что текущая версия работает: так проще понять, что именно сломало обновление.
