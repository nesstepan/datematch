# Выкладка DateMatch на Railway (простыми словами)

Эта инструкция для тех, кто делает это впервые. Все непонятные слова объяснены в словарике ниже. Данные сайта по-прежнему хранятся в Firebase, поэтому пользователи, пары и сообщения **не потеряются**: меняется только место, где «живёт» программа.

## Чем Railway отличается от Render
* **Не засыпает.** На бесплатном Render сайт «засыпал» после 15 минут без посетителей и просыпался минуту. Railway работает постоянно.
* **Деньги.** Новому аккаунту Railway дарит разовые 5 долларов на 30 дней (карту обычно не просят). После этого есть бесплатный план с небольшим ежемесячным кредитом (около 1 доллара), либо платный Hobby за 5 долларов в месяц. Маленький сайт обычно укладывается в 1–5 долларов в месяц. Точные цифры меняются, смотрите на https://railway.com/pricing и в разделе **Usage** своего проекта.
* **Если деньги закончились,** сайт остановится. Поэтому в Railway стоит включить лимит расходов (Usage → лимит) и проверить баланс перед защитой.

## Словарик
* **Репозиторий** — папка с файлами проекта на GitHub (у вас это `nesstepan/datematch`).
* **Деплой** (развёртывание) — когда Railway берёт файлы из репозитория, собирает из них сайт и запускает его на своём компьютере (сервере).
* **Переменная окружения** — настройка, которая хранится не в файлах проекта, а в панели Railway. Так прячут пароли и ключи.
* **Домен** — адрес сайта в интернете, например `datematch-production.up.railway.app`.
* **Логи** — «дневник» программы: Railway пишет туда, что происходит. Если что-то сломалось, ответ почти всегда в конце логов.
* **Проверка здоровья (healthcheck)** — Railway сам открывает адрес `/healthz`. Если сайт ответил, значит, он запустился. Если нет, Railway считает деплой неудачным.
* **Gunicorn** — программа, которая запускает Django-сайт и принимает запросы от посетителей.

## Что уже подготовлено в проекте

### Файл `railway.json`
Это инструкция для Railway, как запускать сайт. Разберём построчно.

```json
{
  "$schema": "https://railway.app/railway.schema.json",
  "deploy": {
    "startCommand": "gunicorn config.wsgi:application --workers 2 --threads 4 --worker-class gthread --timeout 120 --bind 0.0.0.0:$PORT",
    "healthcheckPath": "/healthz",
    "healthcheckTimeout": 120,
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 10
  }
}
```
* `{` и `}` — начало и конец файла. Файл написан на языке JSON: это просто список «название: значение».
* `"$schema": ...` — подсказка для редакторов кода, по какому образцу проверять файл. На работу сайта не влияет.
* `"deploy": {` — раздел «как запускать».
* `"startCommand": "gunicorn ..."` — команда, которой запускается сайт. Её части:
  * `gunicorn` — запускающая программа;
  * `config.wsgi:application` — где у проекта «точка входа» (файл `config/wsgi.py`);
  * `--workers 2` — два параллельных «работника», чтобы сайт отвечал нескольким людям сразу;
  * `--threads 4 --worker-class gthread` — каждый работник умеет делать 4 дела одновременно (нужно, чтобы чат и просмотр видео не «вешали» сайт);
  * `--timeout 120` — ждать ответа до 120 секунд (нужно для загрузки видео с медленного интернета);
  * `--bind 0.0.0.0:$PORT` — слушать запросы по порту, который выдаст Railway. `$PORT` — это значение переменной `PORT`, Railway подставляет его сам.
* `"healthcheckPath": "/healthz"` — какой адрес открывать для проверки здоровья.
* `"healthcheckTimeout": 120` — ждать, пока сайт запустится, до 120 секунд.
* `"restartPolicyType": "ON_FAILURE"` — если сайт упал из-за ошибки, перезапустить его.
* `"restartPolicyMaxRetries": 10` — но не больше 10 раз подряд, чтобы не крутиться бесконечно.

### Файлы `.python-version` и `runtime.txt`
В них записана версия Python (3.12), чтобы Railway собрал сайт на той же версии, на которой он проверялся.

### Что добавлено в `config/settings.py`
```python
_railway_host = os.environ.get("RAILWAY_PUBLIC_DOMAIN")
if _railway_host:
    ALLOWED_HOSTS += [_railway_host, "healthcheck.railway.app"]
    CSRF_TRUSTED_ORIGINS.append(f"https://{_railway_host}")
```
* Первая строка берёт из переменной `RAILWAY_PUBLIC_DOMAIN` адрес вашего сайта. Railway создаёт её сам, когда вы получаете домен.
* `if _railway_host:` — «если адрес есть, то делаем следующее».
* `ALLOWED_HOSTS` — список адресов, по которым Django согласен отвечать (защита от подделки адреса). Мы добавляем в него ваш домен и служебный адрес `healthcheck.railway.app`, с которого Railway делает проверку здоровья. Без второго адреса проверка не проходит.
* `CSRF_TRUSTED_ORIGINS` — список адресов, которым Django доверяет при отправке форм (защита от подложных форм). Добавляем ваш адрес с `https://`.
* Ещё одна строка читает переменную `DJANGO_CSRF_ORIGINS`: пригодится, если вы подключите свой домен (например, `site.ru`).

## Шаги

### Шаг 1. Обновите файлы на GitHub
Нужно положить в репозиторий новые файлы: `railway.json`, `.python-version`, `runtime.txt` и изменённый `config/settings.py` (плюс всё остальное из архива `datematch_update.zip`).
1. Распакуйте `datematch_update.zip`.
2. Откройте https://github.com/nesstepan/datematch → **Add file → Upload files**.
3. Перетащите содержимое распакованной папки (файлы с точкой в начале, например `.python-version`, видны, если включить «Показывать скрытые элементы» в проводнике).
4. Нажмите **Commit changes**.

### Шаг 2. Зайдите в Railway
1. Откройте https://railway.com и нажмите **Login → Login with GitHub**. Разрешите доступ.

### Шаг 3. Создайте проект из репозитория
1. Нажмите **New Project → Deploy from GitHub repo**.
2. Если репозитория `datematch` в списке нет, нажмите **Configure GitHub App**, выберите свой аккаунт и разрешите доступ к `datematch`, затем вернитесь.
3. Выберите `nesstepan/datematch`. Railway сам определит, что это Python, и начнёт первую сборку. Она, скорее всего, **не удастся**, потому что ещё нет переменных. Это нормально.

### Шаг 4. Добавьте переменные
Откройте сервис (плитка с названием репозитория) → вкладка **Variables** → **New Variable** (или **Raw Editor**, чтобы вставить несколько сразу).

| Переменная | Что вписать |
|---|---|
| `DJANGO_SECRET_KEY` | Длинный случайный набор символов. Получить его можно командой `python -c "import secrets; print(secrets.token_urlsafe(50))"` на своём компьютере. Если Python недоступен, придумайте строку из 50 случайных букв и цифр |
| `DJANGO_SSL_REDIRECT` | `1` (включает безопасное соединение https) |
| `ADMIN_EMAILS` | Ваш email: с ним вы получите доступ к админ-панели |
| `FIREBASE_CREDENTIALS_JSON` | **Весь текст** файла-ключа из Firebase (от первой `{` до последней `}`), скопированный целиком |

Не добавляйте `USE_MEMORY_DB` и `PORT`: порт Railway выдаёт сам.

Ключ Firebase возьмите тот же, что вы вставляли в Render: Firebase Console → шестерёнка → Project settings → Service accounts → Generate new private key (новый ключ создаст новый файл, старый можно будет удалить).

### Шаг 5. Получите адрес сайта
1. Откройте сервис → **Settings → Networking → Public Networking → Generate Domain**.
2. Если Railway спросит порт, впишите значение переменной `PORT` (его видно во вкладке Variables). Если не спрашивает, ничего вписывать не нужно.
3. Появится адрес вида `datematch-production.up.railway.app`.
4. **Важно:** после создания домена нажмите на сервисе **Redeploy** (перезапуск). Адрес сайта попадает в программу только при запуске, поэтому до перезапуска она его не знает и ответит ошибкой 400.

### Шаг 6. Дождитесь деплоя
Во вкладке **Deployments** откройте последнюю запись → **View logs**. Когда появится слово **Active** (или «Success») и в логах будет строка про `Listening at`, сайт запущен.

### Шаг 7. Проверка
1. Откройте `https://ВАШ-АДРЕС/healthz`: должно появиться слово `ok`.
2. Откройте главную страницу.
3. Зарегистрируйтесь с email из `ADMIN_EMAILS`. В шапке появится значок щита (админ-панель).
4. Зарегистрируйте второй аккаунт в другом браузере, поставьте друг другу лайки, откройте чат.
5. В Firebase Console → Firestore → Data должны быть ваши данные (они те же, что были на Render).

### Шаг 8. Выключите сайт на Render (по желанию)
Чтобы не было двух копий: https://dashboard.render.com → сервис `datematch` → **Settings** → прокрутите вниз → **Delete Web Service**. Данные в Firebase при этом не удаляются.

## Как обновлять сайт на Railway
Так же, как раньше: загрузили новые файлы на GitHub → Railway сам заметил новый коммит (сохранённое изменение) и пересобрал сайт. Ход виден во вкладке **Deployments**. Подробнее: `docs/09_UPDATING_THE_SITE.md`.

## Если что-то не работает
| Что видите | Что делать |
|---|---|
| «Railpack could not determine how to build» | Railway не нашёл `requirements.txt` в корне репозитория. Файлы проекта должны лежать прямо в корне, а не в папке внутри репозитория. Если они в папке, задайте её в Settings → Source → **Root Directory** |
| Деплой «Failed», в логах `healthcheck failed` | Откройте логи: в конце будет причина. Чаще всего не заданы `DJANGO_SECRET_KEY` или `FIREBASE_CREDENTIALS_JSON` |
| `Задайте переменную окружения DJANGO_SECRET_KEY` | Добавьте переменную (шаг 4) |
| Страница «Bad Request (400)» | Адрес сайта не известен программе: после создания домена нажмите **Redeploy**. Для своего домена добавьте переменную `DJANGO_ALLOWED_HOSTS` |
| Ошибка CSRF (403) при входе или регистрации | Откройте сайт по `https://`, обновите страницу (Ctrl+F5). Для своего домена добавьте `DJANGO_CSRF_ORIGINS=https://ваш-домен` |
| `Firebase не настроен` / `Could not deserialize key` | Ключ вставлен не целиком или повреждён: вставьте содержимое файла ещё раз, ничего не редактируя |
| Сайт без стилей | Нажмите Ctrl+F5 |
| Сайт остановился, в Usage ноль | Закончился кредит: в Railway выберите платный план Hobby или пополните баланс |

## Свой домен (необязательно)
Settings → Networking → **Custom Domain** → введите домен → Railway покажет запись, которую нужно добавить у регистратора домена. Затем добавьте переменные `DJANGO_ALLOWED_HOSTS=ваш-домен` и `DJANGO_CSRF_ORIGINS=https://ваш-домен`.
